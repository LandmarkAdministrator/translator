# Pipeline benchmark — full report

**Target hardware:** 32 GiB RAM + RTX 3060 (12 GiB VRAM)
**Benchmark host:** old-translate PC (16 GiB RAM + RTX 3060)
**Audio:** `tests/ab_test/audio/stitched_test.wav` — 59:57 of speech (JFK × 2 + Jobs × 2)
**Runs:**
- ASR + translation: `tests/benchmarks/20260514_154918/`
- TTS + simul-load: `tests/benchmarks/20260515_123305/`

## ASR — Parakeet 0.6B family (via onnx-asr)

Every variant ran on **30-second chunks**, totaling 60 minutes of audio. RTF is total inference time ÷ audio duration; smaller is better.

| Model | Device | RTF | × realtime | VRAM peak* |
|---|---|---:|---:|---:|
| nemo-parakeet-ctc-0.6b | CPU | 0.021 | **48×** | n/a |
| nemo-parakeet-ctc-0.6b | CUDA | 0.003 | **333×** | n/a |
| nemo-parakeet-rnnt-0.6b | CPU | 0.025 | 40× | n/a |
| nemo-parakeet-rnnt-0.6b | CUDA | 0.008 | 125× | n/a |
| nemo-parakeet-tdt-0.6b-v2 | CPU | 0.022 | 45× | n/a |
| nemo-parakeet-tdt-0.6b-v2 | CUDA | 0.004 | 250× | n/a |
| **nemo-parakeet-tdt-0.6b-v3** | **CPU** | **0.027** | **37×** | **n/a** |
| **nemo-parakeet-tdt-0.6b-v3** | **CUDA** | **0.005** | **200×** | **n/a** |

*onnxruntime uses its own CUDA allocator, not PyTorch's, so `torch.cuda.max_memory_allocated()` reads 0. From the simultaneous-load run we know the Parakeet model adds negligible VRAM to the torch-allocated total. Disk size ~600 MiB.

**Verdict:** Even CPU is 37× faster than realtime — ASR will never be the bottleneck. Pick TDT v3 for the multilingual coverage and newest training.

| nllb-200-3.3B | ht | CUDA fp16 | 462 | 174.2 s | 2.74 | 0.048 | 21× |

**VRAM** (inferred from simultaneous-load test):
- NLLB-1.3B fp16: **~2.5 GiB**

**Verdict:** 3.3B is only ~25% slower than 1.3B but uses ~3× the VRAM. That VRAM matters for the headroom analysis below.

## Simultaneous load — does the production stack fit?

| Configuration | Peak VRAM | Peak RSS | Fits 12 GiB? |
|---|---:|---:|:---:|
| Parakeet (CPU) + **NLLB-1.3B** (CUDA fp16) + Kokoro (CPU) + MMS-TTS (CUDA) | **2.77 GiB** | 14.2 GiB | **✓** (9.2 GiB free) |
| Parakeet (CPU) + **NLLB-3.3B** (CUDA fp16) + Kokoro (CPU) + MMS-TTS (CUDA) | — | — | **✗** crashed during NLLB-3.3B load |

The production stack with NLLB-1.3B uses **less than a quarter** of the 3060's VRAM. The 3.3B stack doesn't fit alongside the other GPU-resident models.

## Recommendation — given "ASR > translation" priority

**Production stack:**

| Stage | Model | Device | RTF | VRAM | RSS impact |
|---|---|---|---:|---:|---:|
| ASR | nemo-parakeet-tdt-0.6b-v3 | **CPU** | 0.027 | 0 | ~600 MiB |
| Translation | facebook/nllb-200-distilled-1.3B (fp16) | **CUDA** | 0.037 | ~2.5 GiB | ~5 GiB |
| Spanish TTS | hexgrad/Kokoro-82M (em_alex) | **CPU** | 0.130 | 0 | ~3 GiB |
| Haitian TTS | facebook/mms-tts-hat | **CUDA** | 0.012 | ~0.5 GiB | ~1 GiB |
| **Total** | | | | **~3 GiB / 12 GiB** | **~10 GiB / 32 GiB** |

Why this layout:

- **Parakeet on CPU** — Saves the GPU for translation. RTF 0.027 = 37× realtime, way more headroom than needed. Frees VRAM that bigger ASR upgrades can claim later.
- **NLLB-1.3B on GPU** — Frees ~4 GiB of VRAM vs 3.3B. That headroom is what lets us upgrade ASR later.
- **Kokoro on CPU** — Saves another ~1 GiB VRAM, costs only ~5 min over a 60-min run.
- **MMS-TTS on GPU** — Small (~0.5 GiB) and the GPU version is 9× faster than CPU.

**~9 GiB VRAM stays free** on the 3060 for future ASR upgrades. Headroom analysis:

| Future ASR upgrade | VRAM cost | Fits in 9 GiB? |
|---|---:|:---:|
| Parakeet 1.1B onnx (when available) — streaming | ~1.3 GiB | ✓ easy |
| Canary 1B with chunked wrapper | ~1.5 GiB | ✓ |
| Whisper large-v3-turbo with chunked wrapper | ~1.5 GiB | ✓ |
| Canary-Qwen 2.5B (chunked) — current open-source WER ceiling | ~5 GiB | ✓ still fits |

If we'd shipped NLLB-3.3B instead, **none** of those upgrades would fit alongside it.

## What changed since the prior 60-min comparison (laptop, AMD iGPU)

Same audio file, different hardware. RTX 3060 vs AMD Radeon 890M, fp16 NLLB vs bf16, CUDA Parakeet provider actually loading.

| Metric | AMD iGPU (prior run) | RTX 3060 (this run) | Speedup |
|---|---:|---:|---:|
| Parakeet TDT v3, CUDA RTF | n/a (silent CPU fallback) | 0.005 | enabled |
| NLLB-1.3B per-sentence avg | 1.24 s | ~0.28 s | ~4× faster |
| NLLB-3.3B usable? | No (bf16 hallucinated) | **Yes** (fp16 works) | — |
| Stack fits on GPU? | Tight | Easy with 1.3B | — |

**The 3060 makes NLLB-3.3B technically viable** (it runs cleanly in fp16, no hallucinations) — but only alone on the GPU, not in the full stack. So it remains a non-option for production unless we move TTS or other models to CPU.

Try community ONNX exports (`jenerallee78`/`dtgagnon`) first; if those fail, proper NeMo export + repackage (4–8 hr work). Deferred until live system stable.

3. **Investigate Moonshine** as a cheap on-CPU quality upgrade — small, edge-targeted, smaller than Whisper-turbo at similar quality.

4. **Real WER measurement on this hardware.** RTF and memory measured here; the actual WER comparison vs the JFK/Jobs reference transcripts is still based on the earlier acoustic-mode run. A clean file-input WER measurement on the 3060 would confirm the choice.

## Caveats

- **VRAM = 0 for ASR** is real but doesn't mean the model is free — onnxruntime uses its own CUDA allocator, which `torch.cuda.max_memory_allocated()` can't see. The simultaneous-load test (2.77 GiB total for Parakeet + NLLB-1.3B + Kokoro + MMS-TTS combined) confirms the addition is small.
- **RSS is cumulative** in our benchmark process. Per-stage CPU impact is estimated. For 32 GiB target host, the 14 GiB peak RSS leaves plenty of headroom.
- **NLLB-3.3B simul-load died during model load**, not inference, so we know the load itself peaks past 12 GiB. The conclusion (doesn't fit in the production stack) holds.
